# ADR-002: Vehicle coordinate frame

- Status: Accepted
- Date: 2026-11

## Context
Phone IMU axes differ from vehicle body axes. The user specified install orientation: screen up, phone top toward vehicle forward. Downstream VBO/Windows tooling expects vehicle channels.

## Decision
Fixed remapping (retain raw phone channels; expose derived vehicle channels):

```
vehicle.X = device.Y
vehicle.Y = -device.X
vehicle.Z = device.Z
```

Attitude uses rotation-matrix transform (not Euler swap). Order: roll X / pitch Y / yaw Z (degrees), right-handed. VBO comments and `data-format.md` describe **vehicle** axes (`Vehicle_*` / `vehicle.*`), not device axes.

## Consequences
- This is install convention, not calibrated zeroing or bias removal.
- Old sessions without `vehicle.*` export NaN on vehicle columns — do not invent historical pose.
- Do not silently change the mapping; any calibration feature must keep raw sensors + parameters.

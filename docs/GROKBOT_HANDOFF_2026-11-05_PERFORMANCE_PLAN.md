## 3. 新模块范围与入口

独立 `performance` 包与“性能测试”页面，从 Dashboard 增加入口。继续使用深色+香槟金、紧凑卡片、横竖屏现有交互，不重写地图/侧栏。

首版四种模式：

| 模式 | 用户参数 | 成绩 |
|---|---|---|
| 起步加速 | 0 → X km/h | 时间 |
| 区间加速 | X → Y，Y>X | 时间 |
| 停车制动 | X → 0 | 时间、距离 |
| 区间制动 | X → Y，X>Y | 时间、距离 |

阈值允许自定义；验证有限值、方向和非负值，使用 Double 统一转为 m/s。不要硬编码只支持 0–100 或 100–0。

用户先选模式/阈值/速度源，点“待命”，再自动检测开始和结束。首版每次待命生成一次成绩，结束后手动再次待命，避免速度抖动产生多条成绩。取消/异常也保留尝试记录与原因。

显示：当前速度、实测采样频率、状态、计时/制动距离、数据质量；结束展示成绩与详情、历史入口。详情显示阈值、有效零速定义、算法版本、时间跨度、质量原因。气压/高度可作为环境上下文，不参与首版成绩修正。

## 4. 架构：一个引擎，实时与重算共用

建议文件职责（新文件，不是当前已有实现）：

- `performance/PerformanceModels.kt`：配置、速度样本、状态、成绩、质量原因。
- `performance/PerformanceEngine.kt`：纯 Kotlin、无 Android/UI 依赖，输入样本和明确的控制事件，输出状态/成绩。
- `performance/SpeedSource.kt`：手机/未来 UM982/CMTS 主机适配接口。
- `performance/PerformanceRepository.kt`：参数、原始速度流、尝试记录、结果版本存储。
- `performance/PerformanceScreen.kt`：设置/待命/成绩；另设历史详情组件。

原始采集 → 速度适配器 → 单线程有序引擎与持久化 → StateFlow UI。实时与离线重算必须调用同一个引擎，禁止两套公式。

复用现有前台采集服务和 HandlerThread/工作线程，不在 Compose 内监听或计算；不得重复注册两套定位监听。先明确“普通录制”和“性能待命”对服务的持有关系：任一需要采集时保持服务，退出性能页不能结束正常录制；普通记录停止不能无提示中断运行中的测试。

引擎状态建议：Idle → Armed/等待条件 → Ready → Running → FinishCandidate → Completed；另有 Cancelled/Invalid。起步确认可有 StartCandidate。候选确认只决定是否接受，不改变原先插值的起止时刻。

速度样本至少包含：

```
sourceId, channelKind, sequence, clockDomain/sessionId
sampleTimeNanos, receivedTimeNanos, utcMillis?
speedMps?, speedAccuracyMps?, valid, mock, rawReference
```

手机使用 `Location.speed` 且检查 `hasSpeed()`；`elapsedRealtimeNanos` 为测量时间，UTC 仅用于展示。新增保存 `hasSpeedAccuracy()/speedAccuracyMetersPerSecond`。当前 phone.gps 尚未保存速度精度，不能拿水平定位精度代替。

Android 官方定义：速度单位 m/s、速度精度为 68% 置信水平、elapsedRealtimeNanos 为单调时钟测量时间。参见 [Location API](https://developer.android.com/reference/android/location/Location)。

未来 UM982 保留设备时间/接收时间及同步映射；CMTS 主机速度注明 GNSS/轮速等通道类型。未完成时钟映射不能冒充同一时间基准。测试中切源/重启/时钟域变化判无效并要求重新待命，禁止拼接来源。

## 5. 阈值与距离算法

相邻有效样本 `(t0,v0)`、`(t1,v1)` 对目标 `V` 的合法方向穿越：

```
alpha = (V-v0)/(v1-v0)
tCross = t0 + alpha*(t1-t0)
```

要求 t1>t0、alpha∈[0,1]、符合升/降速方向、间隔未超过质量规则。不外推、不跨丢失片段插值；v0=v1 不除零。明确端点等于阈值的统一规则，防止重复触发；同一段跨过起终阈值也须正确处理。

时间 = 终点插值时间 − 起点插值时间。先算相对时间差再转 Double，避免巨大时间戳计算损失精度。

制动距离：在起终点切割后的有效速度折线做梯形积分：

```
distanceMeters += (va + vb) / 2 * (tb-ta) / 1e9
```

边界速度使用插值值，内部保留全部真实采样；不使用地图点距离、不用 UI 帧率、不把缺样当零速。定义是“速度区间减速成绩”，不宣称测到了踩刹车瞬间或驾驶员反应时间。

## 6. “0”如何定义（必须在产品与结果中明确）

GNSS 静止可能仍有正速度，不能通过把所有小速度改零来伪造精确零点。建议首版采用公开、可重算的操作定义：

- 静止阈值 `stopSpeedKmh`、持续时间 `stationaryHoldMs`、最少有效样本数。
- 0→X：先满足静止条件，再上穿 `launchSpeedKmh` 计时；launch>stop 构成滞回。
- X→0：下穿 stop 阈值作为候选终点，随后持续静止确认才完成；成绩回溯到候选穿越时刻，不把确认等待算入成绩。
- 结果明确显示“起步阈值… / 停止阈值…”。这种定义不含起步到 launch 的时间，也不含 stop 到真正静止的残余距离；不能包装为精确物理零速结果，更不能与不同定义成绩直接比较。
- 建议初始参数可从 stop=0.5 km/h、launch=1 km/h、静止1秒且至少3个有效样本开始试验，**这些是待实测调参的建议，不是已确认规格**。低频源可能需更长确认时间。
- 首版不做 rollout、坡度或气压补偿；如以后加入，参数和结果版本必须显式记录。

区间测试要求在起点阈值外侧稳定待命后按正确方向穿越；避免启动待命时已越过起点却直接补算。持续回落/反向、超时等由配置定义中止规则，不能把多个不连续尝试拼在一起。

## 7. 质量与异常

每个配置保存缺样上限、过旧上限、确认规则、速度精度阈值、异常判定策略，不允许用后续默认值偷偷重算旧成绩。

- 无速度、NaN/Infinity、负速度、mock 标记、重复/倒序时间戳明确处理并保留原因。
- 速度精度未知标记“未知”，不能当作精度为0；GNSS 位置精度不替代速度精度。
- 丢包/长间隔禁止跨越积分；运行中关键段缺失直接无效。等待阶段可恢复后重新满足待命条件。
- 同时检查样本时间与到达时间；定位完全停更时由服务单调时钟 watchdog 报缺失，不能等下一条消息才发现。
- 滤除点必须保存原始值和判定，不能静默连接两侧。采用后续样本确认阈值穿越；不要过度平滑引入相位延迟，也不要用过低的“最大加速度”过滤真实急加速/急刹车。
- 质量三档：合格（符合所选配置）、警告（低频/精度未知等）、无效（关键缺失/换源/时钟异常等）；同时保存机器可读 reason codes。
- 手机低频 GNSS 的插值只细化穿越估计，不产生新的测量精度。展示实测频率、最大间隔、起止包围样本间隔；不能承诺毫秒精度。UI 建议时间显示到0.01s，但旁边保留质量说明，不把小数位等同准确度。
- 手机与未来外置高频源可设不同质量配置；门限应由采样记录验证，不能仅凭声称10Hz认定“高精度”。

## 8. 存储与重复计算

沿用 `files/sessions/<UUID>/`，建议加 `performance/` 子目录：

```
speed_samples.csv          原始速度+精度+测量/接收时间+来源/质量
attempts/<id>/config.json  schema/算法版本、全部阈值与质量配置、来源
attempts/<id>/result-v1.json
attempts/<id>/result-v2.json  重算生成新版本，不覆盖首次结果
```

仍保存现有 `samples.csv` 与 metadata；不要改变旧 CSV 既有列含义。新增速度专用文件补足 speedAccuracy 等字段，需确保与原始定位样本使用共同序号关联。

结果包含原始文件标识/范围及最终校验摘要、起终点包围样本序号与 alpha、时间/距离、样本统计、异常原因、配置快照、引擎版本。文件完成后再做最终 hash；原子写结果，异常退出保留未完成状态。待命开始即记录原始速度；若提供待命前预缓冲，需将真实缓冲样本一起落盘。

后台流式计算，内存有界，不把整场100Hz IMU读入内存。历史重算直接读取原始速度记录或旧会话原始 phone.gps，不能读 Replay 快照/VBO 抽样。旧记录缺速度精度可重算但标记未知；缺起点/终点或静止依据不出伪成绩。

## 9. 实施顺序与验收

1. **引擎与协议先行**：模型/配置/版本、纯 Kotlin 状态机、穿越和积分、JSON结果；用解析解单测证明算法。
2. **手机实时接入**：在服务中分发原始 GNSS、补速度精度落盘、服务持有关系、待命/取消/结果、横竖 UI 与缺样 watchdog。
3. **历史与复算**：尝试列表、质量详情、原始引用、重算新版本；用同一原始序列验证实时和重算一致。
4. **实际调参**：用户做室外/锁屏/布局/实际车辆体验验收；开发者根据记录分析采样频率、静止抖动与缺样。不把模拟数据当实车成绩。
5. **外接源**：待 UM982 解析与 USB 前台生命周期成熟后加适配器；CMTS 主机再接协议/时钟同步，不阻塞手机首版。

关键单测：匀加速解析时间、匀减速解析距离、边界截段、单段双穿越、阈值相等端点、静止抖动、候选回溯、启动已越界、短暂异常尖峰、重复/倒序时间、完全停更、缺样、换源、无效值、取消重开、实时/重算逐项一致。建议构造20→10 m/s、5秒线性减速，预期距离75m，且测试起终阈值不落在原始采样点的情况。

最终验收须区分“算法通过”“手机管线通过”“真实车辆数据验收”。四种模式、自定义阈值、自动起止、历史/重算均完成才称功能完成。
